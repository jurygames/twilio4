# Phase 0 security audit

This audit covers the Twilio4 app in `jurygames-messages/` and both Vercel projects associated with the repository. The `twilio4-messenger` production deployment references the audited `main` commit `b1b4f1b`; no customer numbers, DMN transaction records, or Google Calendar event records were opened.

## Application controls

- Supabase Auth verifies the account on every protected API request. A short-lived `HttpOnly`, `Secure` in production, `SameSite=Strict` cookie holds the access token; a refresh-token cookie is limited to the sign-out endpoint. Sign out revokes the local Supabase refresh session. An already-issued access JWT can remain valid until its bounded 15-minute cookie expiry. The role comes only from trusted `app_metadata.jurygames_messaging_role`, never user-editable metadata.
- Operators may read templates and request a send. Only admins may create, edit, or delete templates. Template writes and sends require same-origin checks and a custom request header.
- Template reads, writes and aggregate send-guard calls use the signed-in user's access token and the public anon key. Summons RLS limits operators to template reads and their own status rows, and permits template writes only to trusted messaging admins. Twilio4 never receives a Summons service-role key. Request bodies cannot replace template text, sender identity, or media URL; a send names a stored template ID.
- The send route fails closed unless all send, consent, and manual-list review switches are enabled, a server-only approval secret is set, a two-minute approval token matches the current operator/template/sender/group/recipient set, and the database claim RPC succeeds. Operators must explicitly acknowledge consent and opt-out review in the preview flow. Voice calls additionally require an explicitly verified narrow callback ingress. Destinations must already be E.164, lists are capped at 50 unique values, provider concurrency is two, and the database guard limits an operator to 10 attempts per hour and prevents duplicate request IDs. Send records contain template ID, counts, coarse provider status, and timestamps only; they contain no phone numbers, message bodies, or provider SIDs.
- Voice status callbacks must pass Twilio signature validation against the configured HTTPS application URL. Callback parameters are not logged or stored.
- `/api/health` is a data-free liveness response. Legacy password checks and local-storage group data are cleared. Manual groups now exist only in page memory.
- Unauthenticated demo sends, arbitrary call/audio test routes, and sender/debug routes have been removed.
- The temporary frontend recommendation is to retain this Pages Router app through the security and contact-service work, now on patched Next.js 15.5.28 with React 18 compatibility. Retire it after the unified Summons messaging page has passed the same access, consent, retention, and provider safeguards; this phase does not migrate the UI.

## Release gates

- Both `twilio4-messenger` and `twilio4-messages` have Vercel SSO enabled for production and previews. Safe authenticated GETs to `twilio4-messenger` returned 200 for `/api/health` and `/api/templates` (23 template records; values suppressed). The deployed source has no app-level authentication on those APIs, so Vercel SSO is its current outer boundary. No send or call endpoint was invoked.
- The `twilio4-messenger` production environment has `SUPABASE_URL`, `SUPABASE_ANON_KEY`, Twilio credentials, sender defaults, and `APP_ENV`, but no service-role key or messaging safety flags. Its Supabase URL identifies an inaccessible legacy project; its template-table grants/RLS and schema could not be audited. `twilio4-messages` has no Supabase variables and its production aliases returned 404. Production remains protected by Vercel SSO until the hardened app is configured against Summons and separately validated.
- The Summons messaging migration is in the Summons repository and has not been applied. It adds only template content, aggregate send-attempt state, and authenticated routines; it contains no customer recipients. Test it against Summons Staging, review security and performance advisories, then apply to production only after the checks pass. Configure Twilio4 with the Summons URL and anon key; do not add a service-role key. Sending remains disabled until the migration, operator roles, consent/opt-out review, manual-list retention review, and callback path are verified.
- Vercel SSO also protects the production callback path. A signed Twilio callback needs a narrowly scoped reachable ingress. Do not disable broad SSO protection to make callbacks work.
- The Summons MCP foundation is a separate, unmerged, disabled, read-only implementation. Its current six tools omit customer contacts and messaging, and all write capabilities remain unimplemented. This phase adds no MCP send or contact tool. The MCP staging OAuth handshake is not yet validated end to end.
- Two browser-only password literals were found only in their original UI files in the indexed Jury Games source and are removed here. They were not server credentials in this app; no other indexed source reuse was found.

Do not enable `MESSAGING_SEND_ENABLED`, `MESSAGING_CONSENT_REVIEWED`, or `MESSAGING_MANUAL_LISTS_REVIEWED` until the database and deployment gates above are closed. Do not add Summons contact data to Twilio4 until the MCP/service boundary and authoritative 48-hour retention behavior have been reviewed in a separate change.
