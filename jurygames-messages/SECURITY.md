# Phase 0 security audit

This audit covers `jurygames-messages/`, the current production deployment, and both Vercel projects associated with the repository. Production now serves the hardened `c3ee646` build. No customer numbers, DMN transaction records, or Google Calendar event records were opened.

## Deployed controls

- Supabase Auth verifies the account on every protected API request. A short-lived `HttpOnly`, `Secure` in production, `SameSite=Strict` cookie holds the access token; a refresh-token cookie is limited to the sign-out endpoint. Sign out revokes the local Supabase refresh session. An already-issued access JWT can remain valid until its bounded 15-minute cookie expiry. Twilio4 resolves roles through the protected Summons `get_jg_messaging_role` RPC on every request: admin comes only from trusted `app_metadata`, while operator access requires the current active, unsuspended Defendant qualification. User-editable metadata is ignored.
- Operators may read templates and request a send. Only admins may create, edit, or delete templates. Template writes and sends require same-origin checks and a custom request header.
- Template reads, writes and aggregate send-guard calls use the signed-in user's access token and the public anon key. Summons RLS limits operators to template reads and their own status rows, and permits template writes only to trusted messaging admins. Twilio4 never receives a Summons service-role key. Request bodies cannot replace template text, sender identity, or media URL; a send names a stored template ID.
- The send route fails closed unless all send, consent, and manual-list review switches are enabled, a server-only approval secret is set, a two-minute approval token matches the current operator/template/sender/group/recipient set, and the database claim RPC succeeds. Operators must explicitly acknowledge consent and opt-out review in the preview flow. Voice calls additionally require an explicitly verified narrow callback ingress. Destinations must already be E.164, lists are capped at 50 unique values, provider concurrency is two, and the database guard limits an operator to 10 attempts per hour and prevents duplicate request IDs. Send records contain template ID, counts, coarse provider status, and timestamps only; they contain no phone numbers, message bodies, or provider SIDs.
- Voice status callbacks must pass Twilio signature validation against the configured HTTPS application URL. Callback parameters are not logged or stored.
- `/api/health` is a data-free liveness response. Legacy password checks and local-storage group data are cleared. Manual groups now exist only in page memory.
- Unauthenticated demo sends, arbitrary call/audio test routes, and sender/debug routes have been removed.
- The temporary frontend recommendation is to retain this Pages Router app through the security and contact-service work, now on patched Next.js 15.5.28 with React 18 compatibility. Retire it after the unified Summons messaging page has passed the same access, consent, retention, and provider safeguards; this phase does not migrate the UI.

## Live deployment audit and release gates

- Vercel SSO remains enabled on both `twilio4-messenger` and `twilio4-messages`. Before release, a Vercel-SSO-authorized `GET /api/templates` returned the 23-record template catalogue without an app login, and the old `/api/health` exposed a template-count field. After release, `/api/templates` returns `authentication_required` without an app session, while `/api/health` returns only `{"ok":true}`. No send or call endpoint was invoked.
- The `twilio4-messages` production aliases return 404 for the safe health and templates GETs. Vercel environment settings for `twilio4-messenger` target Summons Production, and Preview/Development target Summons Staging. Twilio credentials, sender defaults, and `APP_ENV` are preserved; no service-role key or send-enablement flags are present. Keep Vercel SSO enabled.
- The Summons messaging migrations are merged and installed in both Staging and Production. Each has 23 unique template rows and zero send attempts; neither stores recipient numbers. RLS is enabled, anonymous SELECT is denied, and no new messaging security finding appeared in the post-migration advisors.
- `info@jurygames.com` has the trusted admin claim in Production. Six active Defendant-qualified staff accounts are linked to Summons Auth; their operator access is derived live from Summons records and is not copied into user metadata. The dynamic-role migration is merged and installed in Production. The separate recipient-service PR is not yet deployed, so Twilio4 is not fetching Summons contact lists.
- The separate Summons recipient-service PR is read-only and not deployed. Consent and opt-out evidence is not recorded, so the send and callback gates remain disabled until the consent review, manual-list retention review, and signed callback path are complete. Do not disable broad Vercel SSO to make callbacks work.
- Two browser-only password literals found in the original UI files are removed here. They were not server credentials in this app; no other indexed source reuse was found.

Do not enable `MESSAGING_SEND_ENABLED`, `MESSAGING_CONSENT_REVIEWED`, or `MESSAGING_MANUAL_LISTS_REVIEWED` until the database and deployment gates above are closed. Do not add Summons contact data to Twilio4 until the MCP/service boundary and authoritative 48-hour retention behavior have been reviewed in a separate change.
